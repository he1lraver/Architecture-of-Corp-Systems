# Отчёт по практике 1 — Jakarta EE

Начальная версия: Jakarta EE, JPA, EJB и HTML-формы.

## Предметная область и модель

Приложение ведёт библиотечный каталог. `Author` содержит id, имя, страну и год рождения. `Book` содержит id, название, год издания, цену, остаток и ссылку на автора. У одного автора может быть несколько книг; каждая книга имеет одного автора. В SQL связь закреплена внешним ключом `books.author_id → authors.id`.

Модель представлена JavaBeans: закрытые поля, конструкторы без аргументов и методы чтения и изменения свойств. `@Entity`, `@Table`, `@Id`, `@GeneratedValue`, `@Column`, `@ManyToOne` и `@JoinColumn` связывают Java-модель с таблицами. Цена хранится как `BigDecimal` и `NUMERIC(12,2)`.

Для локального запуска используется файловая реляционная СУБД H2. `database/schema.sql` создаёт таблицы, `database/seed.sql` добавляет двух авторов и три книги. При повторном запуске начальное наполнение не выполняется; изменения сохраняются в `runtime/db/library.mv.db`.

Правила `Rules`: обязательные имя, страна и название с ограничением длины; год от 1 до текущего года плюс один; неотрицательные цена и остаток; не более двух десятичных знаков цены. Нельзя удалить автора, пока у него есть книги. Формы экранируют пользовательский текст при выводе.

## Три слоя и сценарий операции

Данные находятся в `src/main/java/edu/masters/domain`: JPA-сущности `Author` и `Book`, а также правила допустимых значений `Rules`. Бизнес-слой — `ee/LibraryService.java`, сессионный EJB с `@Stateless`. Представление — `ee/LibraryServlet.java` и `view/Html.java`.

Servlet разбирает параметры формы и вызывает EJB. Сервис проверяет значения, получает или создаёт сущность и работает с `EntityManager`. Контейнер WildFly управляет транзакцией. `LibraryException` с `@ApplicationException(rollback=true)` отменяет операцию при нарушении бизнес-правил. После успешного POST выполняется перенаправление к каталогу.

`META-INF/persistence.xml` ссылается на `java:/jdbc/LibraryDS`, использует JTA и проверяет готовую схему через Hibernate. SQL не находится в представлении, HTML не формируется в сервисе. Для этой небольшой модели отдельный DAO, дублирующий операции `EntityManager`, не введён.

## Установка и развёртывание

`SETUP.cmd` устанавливает локальные инструменты. WildFly 39.0.1.Final выполняется на JDK 21; H2 входит в сервер. `START.cmd` создаёт файловую БД, копирует собственную конфигурацию из `server/` в `runtime/server/configuration`, запускает сервер и через административный CLI создаёт `LibraryDS` и развёртывает `target/library.war`.

Развёртывание не использует IDE. Выполненные команды сохраняются в `runtime/configure.cli`; их источник — `scripts/start.ps1`. Конфигурация и данные сервера принадлежат этой практике. Каталог установленного WildFly используется для исполняемых файлов и библиотек.

В консоли администратора доступны Deployments для просмотра WAR, Configuration для источников данных и Runtime для состояния служб. Учебный пользователь: `student`, пароль: `Study-Local-2026!`. Для демонстрации консоли откройте её адрес в обычном браузере. Состояние развёртывания проверено через административный CLI. Графический просмотр консоли в результаты проверки не включён.

## Результаты и границы проверки

Приложение собрано Maven и запущено с файловой БД. HTTP-проверки в `scripts/integration_test.py` проверяют реальные ответы и сохранение изменений; их результаты находятся в `evidence/integration-results.json`. Работоспособность этой версии проверяется через HTTP на запущенном WildFly.

Нагрузочные испытания и аварийное восстановление не проверялись. Подробный список выполненных проверок — в `evidence/VERIFIED.md`.
