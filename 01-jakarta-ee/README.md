# Практика 1 — Jakarta EE

Самостоятельная версия приложения «Библиотека». Начальная версия: Jakarta EE, JPA, EJB и HTML-формы.

## Запуск

1. Запустите `START.cmd` из этой папки. Дождитесь `READY`.
2. Откройте [приложение](http://127.0.0.1:18180/library/ui).
3. Для остановки используйте `STOP.cmd` этой папки.

Если папка перенесена на другой компьютер или извлечена из отдельного архива, сначала выполните `SETUP.cmd`, затем `BUILD.cmd` и `START.cmd`. Установка скачивает закреплённые инструменты в локальную `.tools`; требуется интернет. Код и SQL соседних практик не нужны.

В общем комплекте можно использовать одну установленную `.tools` в родительской папке. Это необязательный кэш инструментов: если его нет, отдельная практика использует собственную `.tools`. Для уже установленного набора инструментов можно задать `PRACTICE_TOOLS`. Эта переменная не указывает на исходники другой практики.

## Файлы

- `pom.xml` и `src/` — собственная сборка и полный исходный код.
- `database/` — создание и начальное заполнение БД.
- `scripts/` — установка, сборка, запуск, остановка и проверки.
- `practice.json` — номер этапа и порты.
- [REPORT.md](REPORT.md) — архитектура, решения и сценарии демонстрации.
- [REQUIREMENTS.md](REQUIREMENTS.md) — соответствие каждому пункту задания.
- `assignment/` — неизменённый оригинал и полный текст задания.
- `evidence/` — результаты проверок.

## Сборка и проверка

После изменения исходников: `STOP.cmd` → `BUILD.cmd` → `START.cmd` → `TEST.cmd`.

`BUILD.cmd` выполняет Maven clean verify и создаёт `target/library.war`. `TEST.cmd` выполняет самостоятельные HTTP-проверки через Python 3 со стандартной библиотекой. Для проверок нужен Python 3 в PATH, стандартный Windows launcher `py` или путь к интерпретатору в `PRACTICE_PYTHON`. Для самого приложения Python не требуется.

Проверки создают временные данные с уникальными именами и удаляют их через приложение. При аварийном завершении незавершённые тестовые записи можно убрать формами. Результаты сохраняются в `evidence/integration-results.json`; журнал сборки — `evidence/build.log`.

## Данные и перенос

У этой практики собственная файловая БД `runtime/db/library.mv.db`. Начальные строки добавляются только при первом запуске. Остановка и повторный запуск не сбрасывают данные. Для переноса рабочего состояния сначала выполните `STOP.cmd` и копируйте папку вместе с `runtime/`. Для сдачи чистого проекта используйте отдельный архив, созданный общим `EXPORT.cmd`: рабочая БД, инструменты и результаты сборки туда не включаются.

Скрипты запуска проверяют PID вместе со временем создания процесса, чтобы остановка одной практики не завершала чужой процесс. Порты различаются между этапами. В `practice.json` для WildFly значения должны соответствовать формулам `httpPort = 8080 + offset`, `managementPort = 9990 + offset`. Если порт занят, запуск сообщает об этом.

Учебные реквизиты H2: пользователь `sa`, пароль `practice`. Приложение слушает локальный адрес 127.0.0.1.

Консоль WildFly: [открыть](http://127.0.0.1:20090/console/index.html). Пользователь `student`, пароль `Study-Local-2026!`. Развёртывание WAR выполняется административным CLI, без IDE.
